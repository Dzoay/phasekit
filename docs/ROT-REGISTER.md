# phasekit rot register

**Status:** living. Every CoolProp problem found, how phasekit designs it out ([ARCHITECTURE.md](ARCHITECTURE.md)),
and the test that proves it; [DECISIONS.md](DECISIONS.md) overrides anything older.

## 1. How to use this register

"Rot" is every defect class the 15 CoolProp v8.0.0 maps ([docs/coolprop-map](coolprop-map)) found: bugs, hazards, dead
code, data errors, weak tests. A row is one class: how phasekit keeps it out, what proves it, and when the proof lands.
The evidence (CoolProp's file and line, the measurement) is the map item the row cites.

| Column | Meaning |
|---|---|
| ID | `ROT-NNN`, stable: a new row takes the next free number; rows are never renumbered, reused or deleted. |
| Source | Every map item merged into the row ("map NN R5", "map NN §6 row 3", map 12's Linear ids "COO-n"), then related items in "(also ...)". |
| Problem | The defect class. |
| Mechanism | What in phasekit makes it impossible, caught or irrelevant. A bare "§N" or "DN" is ARCHITECTURE.md's; other citation forms are [PLAN.md §2.1](PLAN.md#21-ids-and-references)'s; [square brackets] mark a proposal not yet in ARCHITECTURE.md. |
| Proof | The test, lint or gate that shows the mechanism works: `crate::module::test`, or `<file>.rs::test` for an integration test of `phasekit-verify/tests/`. A delivered proof carries its step, `[M6.2]`; an unwritten one reads "new `name` (Mk)", the name a suggestion and the milestone binding. |
| Milestone | When the proof first runs: M0-M10, then PLAN.md §4's numbers; "post-0.1" for later work without a number; "n/a" when nothing is built. |
| Status | One of the values below. |

| Status | Meaning |
|---|---|
| Designed-out | A type or API makes the defect impossible: it cannot be written, or cannot be reached. |
| Test-guarded | A named test proves the mechanism: the defect could be written, and the test would fail. |
| Lint-guarded | A clippy lint, compiler setting or CI gate forbids it. |
| Not-ported | The CoolProp feature that carries the defect is deliberately not ported. |
| Deferred: *trigger* | Belongs to a family or feature after v0.1; the row reopens when its trigger fires, and the family's plan turns it into a mechanism and a proof. |
| Accepted | Deliberately kept, e.g. a v8.0.0 quirk the user chose to keep inside the Tier A CoolPropLib.h shim. |
| GAP | Nothing addresses it yet; it needs a PLAN.md step. |

**Workflow.** PLAN.md assigns each row to the step that writes its proof (each milestone's **ROT rows** line), and that
step's PR ticks it ([PLAN.md §2.1](PLAN.md#21-ids-and-references)). `cargo xtask gates rot` fails when a row of a
closed milestone is GAP or still has a due proof marked new, when a proof names a test that does not exist, and when a
proof marked new already exists. Write the proof first (red), then the mechanism; a proof that cannot be written as
described makes the row GAP. New rot, in CoolProp or in phasekit, gets a row with the next ID and a Source such as
"found M7" or an issue id. A rot row records a defect class; a divergence entry (DIV-nnnn, VERIFICATION.md §6) records
one numeric difference from the oracle, and a row may cite one as its proof.
