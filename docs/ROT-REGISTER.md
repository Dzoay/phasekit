**Status:** written 2026-10-05 for the plan-doc stage and revised the same day after two reviews ([design/05-plan-review-log.md](design/05-plan-review-log.md)), against the final [ARCHITECTURE.md](ARCHITECTURE.md) and the user decisions in [04-user-decisions.md](design/04-user-decisions.md). ## 1. How to use this register

"Rot" is every defect class the 15 CoolProp v8.0.0 maps ([docs/coolprop-map](coolprop-map)) found: bugs, hazards, dead code, data errors, weak tests. Each row says how phasekit keeps that class out, what proves it, and when the proof lands.

**Columns.**

| Column | Meaning |
|---|---|
| ID | `ROT-NNN`, stable. A new row takes the next free number; rows are never renumbered or reused. |
| Source | Every map item merged into the row ("map NN R5", "map NN section 6 row 3", map 12's "COO-n"), then related items in "(also ...)". Search this column for any map ID. |
| CoolProp location | File:line in `reference/CoolProp` (v8.0.0) unless the cell gives a commit, an issue (#n), a bead (bd:x), a Linear id (COO-n) or "oracle" (observed with the CoolProp 8.0.0 wheel). |
| Problem | The defect, with the evidence the map gives. |
| Mechanism | What in phasekit makes the defect impossible, caught or irrelevant. |
| Proof | The test, lint or gate that shows the mechanism works (notation below). |
| Milestone | When the proof first runs: M0-M10 as in ARCHITECTURE.md D15; after v0.1 the PLAN.md §4 numbers (M11 cubic, M13 mixtures, M14 IAPWS, M15 PC-SAFT, M16 Python, M17 INCOMP, M18 humid air, M19 plotting); "post-0.1" only for later work that has no milestone number; "n/a" when nothing is built. A row whose proof has parts at two milestones lists both ("M6, M7"); a part due later than the first carries "(Mk)" after its test name. |
| Status | One of the seven values below. |

**Status values.**

| Status | Meaning |
|---|---|
| Designed-out | A type or API makes the defect impossible (it cannot be written, or cannot be reached). |
| Test-guarded | A named test proves the mechanism; the defect could be written, and the test would fail. |
| Lint-guarded | A clippy lint, compiler setting or CI gate forbids it. |
| Not-ported | The CoolProp feature that carries the defect is deliberately not ported. |
| Deferred: *trigger* | Belongs to a family or feature after 0.1; the trigger says when the row reopens. The mechanism column says which seam already exists. |
| Accepted | Deliberately kept, e.g. a v8.0.0 quirk the user chose to keep inside the Tier A CoolPropLib.h shim. |
| GAP | Nothing in the architecture addresses it yet. Section 3 proposes a minimal mechanism and a milestone. |

**Notation.**
- "§N" and "DN" without a file name are ARCHITECTURE.md sections and decisions; "user decision N" is row N of 04-user-decisions.md; "map NN §X" is a map section; DIV-nnnn are divergence-register entries (ARCHITECTURE.md §10, VERIFICATION.md section 6).
- "sketch `name`" is a test that exists and passes in [docs/design/sketch](design/sketch). `lazy_load.rs`, `new_family.rs`, `gibbs_seam.rs` and `register.rs` are integration tests in `phasekit-verify/tests/`; other names are module paths. `phasekit_verify::conformance::{fd_first_order, gauge_invariance, policy_equivalence}` exist in the sketch kit.
- "new `name`" is a proposed test. The name is a suggestion; the milestone is binding.
- "open detail N" is item N of the list at the end of section 3: the rot is handled, but a detail is unspecified.
- Text in [square brackets] is a proposal that is not yet in ARCHITECTURE.md. *(inference)* marks a claim that is not in the maps or research docs, as in ARCHITECTURE.md.

**Workflow.**
- PLAN.md section 3 ends each milestone with a **ROT rows** line that assigns every row of that milestone to the step that writes its proof. The test names in this register's Proof column are normative: where a PLAN.md step names a test for the same check, the two names are the same. VERIFICATION.md section 14 lists the proofs per milestone.
- **Ticking** (PLAN.md §2.1): the step's PR drops the word "new" before each proof it delivers and appends the step id in brackets (`[M6.2]`). `cargo xtask gates rot` (VERIFICATION.md §11.2) fails once a milestone closes if any proof due by it is still marked "new" or any of its rows is still GAP. A milestone is done only when every row with that milestone has its proof running.
- TDD: write the Proof column's test first (red), then the mechanism. For a Designed-out row, a compile-time assertion or a test that drives the API is enough.
- If a proof cannot be written as described, the row becomes GAP and is added to section 3; never delete it.
- New rot found later (in CoolProp or in phasekit): add a row with the next ID, a Source such as "found M7" or an issue id, and the same columns.
- Divergence entries (DIV-nnnn) and rot rows are different things. A DIV entry records a numeric difference from the oracle with a three-part proof (VERIFICATION.md section 6); a rot row records a defect class. A rot row may use a DIV proof as its Proof.

**Open mechanism details.** Each is settled in PLAN.md.

1. **Shim `set_config_*`** (ROT-015, ROT-019). Needs the user (decision 9b says "match v8.0.0 exactly", but v8.0.0 applies all 38 keys through global state): PLAN.md §6 decision 6, whose default is this register's proposal: a shim-only store, read only by shim functions (e.g. `LIST_STRING_DELIMITER` for `get_global_param_string`); keys that change numerics are accepted and ignored, with the list documented. M10.6.
2. **Atomics** (ROT-031): `disallowed-types` for `std::sync::atomic::*` from PLAN.md M0.3; only capi's FFI-state modules may use them (M10.4).
3. **`thread_local!`** (ROT-268): `disallowed-macros` from PLAN.md M0.3; only `phasekit-capi`'s per-thread error may use it.
4. **Filesystem access** (ROT-153): `disallowed-methods` for `std::fs::*` entry points and `std::env::home_dir` from PLAN.md M0.3.
5. **R123 / R11 cp0 `Tc`** (ROT-050): Parity keeps the JSON value; an `Investigate` DIV entry decides Corrected after the paper check (PLAN.md M4.3).
6. **Shim FP-flag semantics** (ROT-151): settled by user decision 9b ("quirks live only in the shim"): the shim clears the caller's sticky flags as v8.0.0 does; `pk_*` restores them (PLAN.md M10.7, one test per facade).
7. **Composite families read borrowed models ungauged** (ROT-104). Proposal: a family that borrows a model (humid air, a cubic's ideal gas) evaluates it through `fluid.model()`, never the gauged `Fluid::flash`; the conformance kit's `gauge_invariance` covers composite outputs. At M11 and M18.
8. **INCOMP needs its own state path** (ROT-258). `bundle_from_gibbs` refuses g_pp ≥ 0, so an incompressible Gibbs form cannot use it *(inference)*; INCOMP builds states through its own `ThermoModel` and `State::from_total`. At M17.
